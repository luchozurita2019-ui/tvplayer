ETAPA 1 - RECONSTRUCCION DE FORMATOS
------------------------------------
Fuente analizada: FútbolTotal_v3.6.apk descompilada.

Se confirmó en el código original:
1. El manifiesto maestro utiliza el formato ft-tv-lists2.json.
2. El manifiesto contiene lists[] con name, url, kind (flow/futbol) y ttl.
3. El bloque futbol admite evento_path, iframe, descartar[] y saltos[].
4. Los catálogos Flow usan seeds[], seed_ua, categories[] y samples[].
5. Cada sample Flow puede contener name, original_url, url, headers, type,
   drm_license_uri/drm e icono/logo.

CAMBIOS DE CODIGO - ETAPA 1
----------------------------
A) lib/services/futbol_total_manifest_parser.dart
   - Parser nuevo e independiente del manifiesto de Fútbol Total.
   - Lee lists[] y reglas remotas de futbol.
   - Normaliza kind vacío a flow.
   - Normaliza TTL negativo a cero.
   - No implementa autenticación ni contiene secretos.

B) lib/services/futbol_total_flow_catalog_parser.dart
   - Parser nuevo para categories/samples.
   - Respeta prioridad original_url -> url.
   - Conserva headers declarados por la fuente.
   - Conserva nombre, categoría y logo HTTP/HTTPS.
   - Lee seeds y seed_ua.
   - En esta etapa WEB/IFRAME y DRM quedan identificados pero no se envían al
     reproductor hasta conectar el resolvedor autorizado.

C) lib/services/futbol_total_catalog_service.dart
   - Fachada de red para cargar un manifiesto autorizado y catálogos Flow.
   - Reutiliza el descargador estable de TV FULL.
   - No altera provider.json, M3U, Xtream, Stalker ni Lista clásica.

D) test/futbol_total_catalog_test.dart
   - Pruebas del manifiesto.
   - Prueba de prioridad original_url.
   - Prueba de fallback url.
   - Prueba de headers.
   - Prueba de omisión controlada de WEB/IFRAME y DRM.

ETAPA 2 - AGENDA DE FUTBOL
---------------------------
E) lib/services/futbol_total_agenda_parser.dart
   - Parser nuevo para la agenda JSON del modo Fútbol.
   - La raíz se interpreta como array JSON, igual que en Fútbol Total 3.6.
   - Lee status, titulo, categoria, ts_utc y canales[].
   - Omite eventos cuyo status contiene "final".
   - Omite canales con con_anuncios=true.
   - Requiere canal_id y usa "Canal" si falta el nombre visible.
   - El título usa titulo -> categoria -> "Partido".
   - canal_id se conserva como identificador y NO se trata como URL multimedia.
   - Se agregó FutbolTotalAgendaReference para reproducir la referencia interna
     observada en la APK: base-origen|canal_id.
   - La base conserva esquema, host y puerto de la URL de agenda.

F) lib/services/futbol_total_catalog_service.dart
   - Ahora también puede descargar y parsear listas kind=futbol.
   - Las listas kind=flow y kind=futbol siguen rutas de parser separadas.

G) test/futbol_total_catalog_test.dart
   - Se agregaron pruebas de eventos finalizados.
   - Se agregaron pruebas de con_anuncios.
   - Se agregó prueba de la referencia base-origen|canal_id con puerto.
